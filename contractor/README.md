# yardplan-contractor (P0 contractor modules)

Plain ES modules, no build step. Work in the browser and in Node ≥18. Nothing here edits `/workspace/yardplan`.

| File | Purpose |
|---|---|
| `takeoff.js` | design → material line items + plant schedule + CSV |
| `pricebook.js` | contractor price book (seeded from app price provider), JSON/localStorage |
| `bid.js` | bid generator (lines, subtotals, overhead, markup, tax, Good/Better/Best) |
| `compliance.js` | "Pro required" flags (walls, surcharge, grading) + standard notices |
| `proposal-pdf.js` | branded client proposal PDF (jsPDF) |
| `sample-data.js` | sample design (yard3d `demo()` + wall/grade), catalog subset, example price provider (generated by `tools/gen-sample.cjs`, which only reads the app) |
| `demo.html` | takeoff, editable price book, bid, "Download proposal PDF" |
| `vendor/jspdf.umd.min.js` | **jsPDF 2.5.2** UMD (MIT, `vendor/LICENSE-jspdf.txt`), from jsdelivr `npm/jspdf@2.5.2/dist` |
| `labor-rates.js` | ZIP → metro → BLS OEWS wage → suggested burdened `hourlyRate`; optional BLS API hook |
| `sanity.js` | installed $/sq ft checks against market ranges |
| `overhead.js` | overhead %, break-even, margin price helpers |
| `data/pricing-defaults.json` (+ `.js`) | research defaults, copied from `yardplan-research/pricing-defaults.json` |
| `data/labor-wages.json` (+ `.js`) | BLS OEWS May 2025 wages (7 occupations; 47 metros, all states, national) + ZIP→CBSA for those metros + ZIP3→state |
| `tests/all.test.js`, `tests/pricing.test.js` | `npm test` runs these plus `p1/tests/` |
| `tools/gen-data-modules.cjs`, `tools/build-labor-data.py`, `tools/demo-smoke.mjs` | regenerate data modules, rebuild the wage data from public files, headless demo check |
| `tools/browser-smoke.mjs` | optional headless check of demo.html (needs `playwright-core` + Chrome, server on :8765) |

Run: `npm test` (or `node --test tests/`). Demo: `python3 -m http.server 8765` in this folder, then open `http://localhost:8765/demo.html`.

## Data model (as found in the app)
- **Design** = `window.yard3dApi.serialize()` in yard3d.js (stored in localStorage `yardplan.design3d.v2`):
  `{ v:2, yard:{w,d}, items:[{ kind:'plant'|'mulch'|'path'|'gravel', id?, x, z, r, w, d }] }`. Feet. For features, `w`×`d` is the rectangle size (mesh scale); `r` is rotation (does not change area). Plants have `id` = catalog id. (Plant items also carry w/d = scale 1; we ignore them.)
- **Catalog** = globals `PLANTS` (`{id,name,sci,type,zmin,zmax,sun,water,size,native,styles,icon}`) and `PLANT3D` (`{model,h,w,leaf,bloom}`) from data.js.
- **Materials** = global `MATERIALS` in prices.js (`{name,unit,price,calc}`), keys `mulch, rock, pavers, sod, topsoil, edging, fabric`.
- **Price provider**: `priceProvider.getPrice(key, zip) → {price, unit, source, store?, asOf, isEstimate}` per app purchase unit. (Note the app's `ExamplePriceProvider` throws on unknown keys; `seedFromProvider` catches and keeps defaults.)

### Contractor extensions (assumptions — the app does not produce these yet)
- `{kind:'wall', w:<length ft>, h:<exposed height ft>, footing:<ft below grade>, surcharge:false|true|'driveway'|'slope'|'structure'}`
- `{kind:'grade', cutCuYd, fillCuYd}` items and/or top-level `design.grading = {cutCuYd, fillCuYd}`.
- Optional `kind:'lawn'` items, or `includeLawn:true` (= yard area minus feature areas, overlaps not subtracted).

## API

### takeoff.js
```js
takeoff(design, { catalog:{plants, plant3d}, waste?:{key:0.1}, includeLawn?:false, recipes?:{kind:[keys]}, containerSizes?:{type|plantId:'5 gal'} })
  → { lines:[{key,name,unit,basis,area,length,volumeCuFt,volumeCuYd,waste,netQty,qty,sources}], plants:[...], featureArea:{kind:sqft}, totals:{plantCount,lineCount} }
plantSchedule(design, opts) → [{id,key:'plant:<id>',name,sci,type,size,native,container,matureH,matureW,count}]
toCSV(takeoffResult) → string
measureItem(item) → {area, perimeter, length, faceArea?}
UNIT_DEFS, DEFAULT_WASTE, FEATURE_RECIPES, DEFAULT_CONTAINER
```
Recipes: mulch → mulch(3")+fabric+edging(perimeter); dg → dg(3" cu yd)+fabric+edging; `{kind:'excavation', w,d,depthIn=6}` or `grade.haulCuYd` → excavation cu yd; `{kind:'drip', zones}` → drip zones (contractor extensions); path → pavers(1/sq ft)+base(4" cu yd)+sand(1" cu yd)+edging; gravel → rock(2")+fabric+edging; lawn → sod+topsoil(4"); wall → wallblock (face sq ft incl. footing); grade → grading cu yd. `qty` is in the app's purchase units (bags, rolls, pavers, pallets) with waste, rounded up (cu yd to 0.1). The app's own `MATERIALS.calc` has no waste for bags, so our bag counts run ~10% higher. Container sizes are defaults by type (tree 15 gal, shrub 5 gal, perennial/grass 1 gal, groundcover 4 in, succulent 5 gal): **assumption**, the catalog has no nursery size.

### pricebook.js
```js
createPriceBook({ materials?:MATERIALS, settings?, items? }) → book
await seedFromProvider(book, priceProvider, zip, keys?) → book   // doesn't clobber overridden items
setItem(book, key, {unitCost?, laborPerUnit?, laborHoursPerUnit?, name?, unit?})   // marks overridden
setPlantPrice(book, plantIdOrContainer, {unitCost, laborPerUnit?|laborHoursPerUnit?})
setSettings(book, {hourlyRate, markupPct, overheadPct, taxPct, taxOn:'materials'|'all', tiers})
toJSON(book) / fromJSON(str|obj) / saveToStorage(book, storage?, key?) / loadFromStorage(storage?, key?)   // key 'yardplan.contractor.pricebook.v1'
```
Labor per line: a flat `laborPerUnit` ($) is used if set, otherwise `laborHoursPerUnit × hourlyRate`. All defaults are EXAMPLE numbers.

### Pricing defaults (since v2 of the price book)
- **`hourlyRate` is the burdened labor COST per billable hour** (wage × (1+burden) ÷ billable ratio), not a sell rate. Overhead and markup go on top: `effectiveSellRate(s) = hourlyRate × (1+OH) × (1+labor markup)`. Defaults 38 × 1.22 × 1.15 ≈ $53/hr.
- `createPriceBook({ materials, settings, items, defaults = 'research' | 'legacy' | {items, plants, settings} })`. `'research'` loads `data/pricing-defaults.json`: items include `dg`, `excavation`, `drip`; plants include 24" box and B&B; settings include hourlyRate 38, overhead 22%, markup 15%, minimum $500, mobilization $150, delivery $100/load, dump $75/load. `'legacy'` gives the original P0 examples.
- `applyDefaults(book, defaults, {materials})` re-seeds and **keeps overrides**: items and plants marked `overridden` by `setItem`/`setPlantPrice`, plus every setting changed via `setSettings` or the `createPriceBook` `settings` arg (tracked in `book.settingsOverridden`).
- New settings fields:
  - `siteDifficulty` (`'easy'|'moderate'|'hard'` or a number)
  - `markups` (`{materials, plants, labor, equipment, subs}` or `null`)
  - `minimumJobCharge`, `mobilizationFee`, `deliveryFeeBulk`, `dumpFeePerLoad`, `bulkLoadCuYd` (10), `dumpLoadCuYd` (6), `feesMarkedUp` (false)
- Items carry `costType` (`material` | `equipment` | `sub`); `grading` is `equipment`.
- `SITE_DIFFICULTY`, `difficultyFactor(d)`, `INSTALLED_PRICE_CHECKS`, `LABOR_REGIONS`, and `PRICING_DEFAULTS_META` are exported. `laborCostPerUnit(e, rate, difficulty=1)` scales hours only; a flat `laborPerUnit` is not scaled.

**Compatibility / breaking changes**
- **Default values changed:** a book created with no `defaults` arg now uses the research numbers. Pass `defaults:'legacy'` to get the P0 numbers back (the P0 bid-math test now does).
- **Automatic fee lines:** research defaults add mobilization, delivery and dump lines, plus a minimum-charge line. Disable them per bid with `generateBid(t, book, {autoFees:false})`.
- **Old saved books:** v1 JSON books (`fromJSON`/`loadFromStorage`) keep their own settings and get neutral new fields (no fees, uniform markup, easy site), so their totals don't change.
- **New totals fields:** `totals` gains `plants`, `equipment`, `subs`, `fees`, `minimumAdjustment`. Existing fields keep their meaning: `materials` still includes plants, and `direct` excludes pass-through fees.

### bid.js
```js
generateBid(takeoffResult, book, { tiers?: true | [{id,name,materialMult,laborMult,overrides:{key:{unitCost}}}] })
  → { lines:[{category:'material'|'plant'|'other',key,description,qty,unit,unitCost,materialCost,laborUnit,laborHours,laborCost,total}],
      subtotals:{material,plant,other}, totals, settings, tiers?:[{id,name,lines,totals}], createdAt }
totalsFor(lines, settings) → {materials,labor,laborHours,direct,overhead,markup,subtotal,tax,total}
```
`generateBid(t, book, { tiers?, autoFees=true, difficulty?, difficultyByKey?:{lineKey:d}, deliveries?, haulCuYd?, dumpLoads? })`.

Math, with lines bucketed by `costType`:
- `direct = materials(+plants) + equipment + subs + labor`
- `overhead = direct × OH%`
- `markup = Σ bucket × (1+OH%) × bucket markup%`. With `markups:null`, every bucket uses `markupPct`, which is identical to P0.
- Fees (`costType:'fee'`) pass through with no overhead or markup unless `feesMarkedUp`.
- `subtotal = direct + overhead + markup + fees`, raised to `minimumJobCharge` with a `fee:minimum` line flagged `adjustment:true`. `totalsFor` ignores that line and recomputes it, so change orders re-total correctly.
- `tax = materials × tax%` (or the subtotal if `taxOn:'all'`); `total = subtotal + tax`.

Automatic fee lines (`feeLines(t, settings, opts)`):
- `fee:mobilization`: 1 per job.
- `fee:delivery`: ceil(bulk cu yd ÷ `bulkLoadCuYd`) loads. Bulk means cu yd lines other than grading and excavation.
- `fee:dump`: ceil((`excavation` cu yd + `opts.haulCuYd`) ÷ `dumpLoadCuYd`) loads.

Site difficulty multiplies `laborHoursPerUnit` (production hours) for all lines, or per line via `difficultyByKey`. Lines that use it show `line.difficulty`.

Margin helpers: `marginToMarkup(m) = m/(1−m)`, `markupToMargin(k) = k/(1+k)` (fractions), `marginPctToMarkupPct(13.04) → 15`, `markupPctToMarginPct(15) → 13.04`, `effectiveSellRate(settings)`.

`book.extras = [{description,qty,unit,unitCost,laborUnit,costType?}]` adds free-form lines (`costType:'sub'` for subcontractors).

### labor-rates.js
```js
lookupArea(zip) → { level:'metro'|'state'|'national', cbsa?, state?, name, wages, estimatedMapping }
suggestLaborRate(zip, { crewMix=[{occ:'37-3011',share:.75},{occ:'37-1012',share:.25}], stat='median'|'mean'|'p25'|'p75'|'p90', burdenPct=30, billableRatio=.85 })
  → { hourlyRate, wage, burdenPct, billableRatio, area:{level,name,cbsa,state}, components:[{occ,title,share,wage,level}], source, notes[], caveat }
burdenedRate(wage, burdenPct=30, billableRatio=.85) = wage × (1+burden) ÷ billable
blsOewsSeriesId({areaType:'M'|'S'|'N', area:'0039900', occ, datatype:'08'|'03'})   // 08 hourly median, 03 hourly mean
await fetchBlsOewsWage({ cbsa, occ, datatype, registrationKey?, fetchImpl? })   // live BLS API: v1 keyless or v2 with key; never called in tests
```
Occupations covered: 37-3011, 37-1012, 37-3012, 37-3013, 47-2061, 47-2073, 53-3032. Usage: `setSettings(book, { hourlyRate: suggestLaborRate(state.zip).hourlyRate })`. Reno 89501 → 37-3011 median $21.64 (2025), crew mix $23.32 → **$35.67/billable hr** burdened.

Data sources (public, no sign-up, downloaded 2026-10-13):
- BLS OEWS **May 2025** `oesm25ma.zip` / `oesm25st.zip` / `oesm25nat.zip` (bls.gov/oes/special-requests/).
- ZIP→CBSA is **estimated**. HUD's USPS crosswalk needs an API token, so the mapping instead uses the Census 2020 ZCTA–county relationship file (county with the largest land share) plus the 2023 OMB CBSA delineation (`list1_2023.xlsx`).
- Covered metros: top 45 by 37-3011 employment, plus Reno, Carson City and Las Vegas. Bridgeport CT has no ZIPs because of the 2023 CT county change, so it falls back to CT statewide.
- ZIPs outside those metros fall back to state (majority state by ZIP3), then national.

### sanity.js
`priceSanityChecks(takeoff, bid, { checks?, regionalMult=1, tierId? }) → [{code, label, area, price, perSqFt, range, status:'low'|'ok'|'high', level, message, source}]`

Checks:
- `paver-patio`: pavers + base + sand ÷ path area.
- `dg`, and `sod` (sod + topsoil ÷ lawn area).
- `retaining-wall`: per sq ft of face.
- `whole-landscape`: subtotal ÷ landscaped area. Range $5–10 softscape, $15–25 with hardscape.

Prices are sell prices (with overhead and markup, before tax, excluding fees and the minimum adjustment). Ranges are national 2026 figures from the research. Use `regionalMult` for regional adjustment (about 1.15–1.3 on the West Coast and in the Northeast).

### overhead.js
`overheadPctOfRevenue(oh, rev)`, `overheadPctOnDirect(oh, rev, {netProfitPct})` (enter this one as `overheadPct`, because bid.js applies overhead to direct cost), `overheadPerFieldHour(oh, hours)`, `breakEvenRevenue(oh, grossMarginPct)`, `breakEvenPrice(direct, ohPct)`, `priceForMargin(direct, ohPct, marginPct)`, `breakEvenHourlyRate(burdenedRate, oh, hours)`, `bidProfit(bid) → {breakEven, netProfit, netMarginPct}`, and `overheadSettings({annualOverhead, annualRevenue, netProfitPct?, targetNetMarginPct}) → {overheadPct, markupPct}` (pass to `setSettings`).

### compliance.js
```js
checkCompliance(design, { wallLimitFt=4, wallWarnFt=3.5, gradingLimitCuYd=50 }) → [{code, level:'error'|'warn'|'info', message, itemIndex?}]
```
Codes: `wall-height` (h+footing > 4 ft), `wall-height-near` (> 3.5 ft), `wall-surcharge`, `grading-volume` (cut+fill > 50 cu yd), plus `conceptual` and `call811` every time. General IRC-based rules; local codes vary.

### proposal-pdf.js
```js
buildProposalPdf({ jsPDF?, business:{name,address,phone,email,license,logo,color:[r,g,b]}, client:{name,address,phone,email},
  project:{title,date,zip,zone}, images:{before, after, renders:[dataURL | {src,caption}]}, renderSlots?:n,
  takeoff, bid, tier?:'good'|'better'|'best', warnings, terms?:string[], validDays?:30, footers?:true }) → jsPDF doc
downloadProposalPdf(opts, filename) → doc   // browser: doc.save()
pdfText(str)   // maps Unicode to WinAnsi-safe text for the standard fonts
```
`footers:false` skips the per-page footer (conceptual/811 + "Page i of n") so callers that append pages can draw it once at the end (see `p1/p1-pdf.js stampFooters`). Images are PNG/JPEG data URLs. Empty slots show a placeholder box. Every page footer reads "Conceptual design, not for construction. Call 811 before you dig." Line amounts shown to the client include overhead and markup spread proportionally (labor and markup are not broken out). Browser: load `vendor/jspdf.umd.min.js` with a `<script>` tag (sets `window.jspdf`). Node: `createRequire(import.meta.url)('./vendor/jspdf.umd.min.js').jsPDF` and pass `{jsPDF}`.

## Grabbing images from the app
- **3D render**: yard3d creates its renderer with `preserveDrawingBuffer:true`, so:
  `yard3dApi.render(); const url = document.querySelector('#yard3dWrap canvas').toDataURL('image/jpeg', .85);`
  For several views, move `yard3dApi.camera()` / `yard3dApi.controls()` (`controls.update()`), then render and capture again. Hide the selection ring by `yard3dApi.select(null)` first, as `#y3png` does. JPEG keeps the PDF small.
- **Before/after**: before = the user's uploaded photo (data URL, or draw it to a canvas). After = the overlay3d.js canvas (check `#tab-overlay canvas`) via `toDataURL`. If its renderer lacks `preserveDrawingBuffer`, call toDataURL right after a render in the same frame. Not verified, because overlay3d.js was not changed.
- The 3D tab must be initialized first (`window.onYard3dShow()`), otherwise `yard3dApi.ready()` returns false.

## Suggested integration snippet (for Boss Bot)
Copy this folder into the app (for example `yardplan/contractor/`), then add a module script after the app scripts:
```html
<script src="contractor/vendor/jspdf.umd.min.js"></script>
<script type="module">
import { takeoff } from './contractor/takeoff.js';
import { createPriceBook, seedFromProvider, loadFromStorage, saveToStorage } from './contractor/pricebook.js';
import { generateBid } from './contractor/bid.js';
import { checkCompliance } from './contractor/compliance.js';
import { downloadProposalPdf } from './contractor/proposal-pdf.js';
// PLANTS, PLANT3D, MATERIALS, priceProvider, state are classic-script globals in data.js/prices.js/app.js
// (priceProvider/state are `let`/`const` at top level: reachable by name from module scripts, not via window.*)
window.makeProposal = async (business, client, photos = {}) => {
  const design = window.yard3dApi.serialize();
  const t = takeoff(design, { catalog: { plants: PLANTS, plant3d: PLANT3D } });
  const book = loadFromStorage() || createPriceBook({ materials: MATERIALS });
  await seedFromProvider(book, priceProvider, state.zip); saveToStorage(book);
  const bid = generateBid(t, book, { tiers: true });
  window.yard3dApi.select(null); window.yard3dApi.render();
  const render = document.querySelector('#yard3dWrap canvas').toDataURL('image/jpeg', .85);
  return downloadProposalPdf({ business, client, project: { zip: state.zip, zone: state.zoneLabel },
    images: { before: photos.before, after: photos.after, renders: [render] }, takeoff: t, bid, warnings: checkCompliance(design) });
};
</script>
```
Caveat: whether top-level `const`/`let` from classic scripts can be read from a module depends on script order. They share the global lexical scope, so it works once the classic scripts have run. Otherwise expose them on `window` explicitly.
